# _CreateTrades

Built in #139 as ticket I4 of the [trade-valuation pipeline](../../engineering-tickets/trade-valuation-pipeline/README.md), with [_CreateTradeTemplate](trade-template.md); the design is [CreateTrades: resolution, encoding and retained state](../../engineering-tickets/trade-valuation-pipeline/create-trade.md).

A batch of trades on one index: the deals a ticket's rows describe, one trade per row, completed with the shared fields a template supplies, resolved against the index and encoded into the static arrays the [kernel](kernel.md) prices. One row is a batch of one and a repeated row is a second trade; the batch is immutable, retains no history, price or valuation date, and is what `_PrepareTrades` takes. The code is `src/catalyst/trades/resolution.py`, the resolution child and the batch, `src/catalyst/trades/template.py`, the readers of each field's value, and `src/catalyst/excel/trades.py`, the worksheet function.

```python
def _CreateTrades(

    trade_rows: FieldRows[TradeTemplate],

```

Five arguments, the first four required and none of them with a default; the fifth, the collection of holiday calendars, is given for a financially settled batch and left out for a physical one, [payment-calendar-keys.md](../../engineering-tickets/trade-valuation-pipeline/payment-calendar-keys.md): the cell showing [_CollectHolidayCalendars](../index-definitions/collect-holiday-calendars.md)'s result, which each row's `payment_holiday_key` selects from, in a cell outside the ticket as the index's is, I5 here: `=_CreateTrades(I3, A4:E4, A5:E9, B3, I5)`. The NG example settles physically and names none. The indexes are the first: the cell showing `_CreateIndex`'s result, or a name for it, the one index every trade of the batch is on, or since [two-index-fixed-float.md](../../engineering-tickets/trade-valuation-pipeline/two-index-fixed-float.md)'s third pull request a row or a column of two such cells for a pair, the first leg's index first, [inputs.md](../../seam/inputs.md) decision 44's form, a wider and taller range refused by its shape, `indexes is 2x2 array, expected one cell, one row or one column of index handles`, and each cell by the handle's rule at its place, `indexes cell (2, 1) is blank, expected index handle`; an index is no template field and no ticket column, so one template serves any compatible index or pair, and the batch retains the indexes it was resolved against. The ticket is two arguments, as a table is: the header row, each header a field name shown by `_ShowInstrument` spelled exactly, case and all, in any order, and the rows under it, one trade each. The template is last: the cell showing `_CreateTradeTemplate`'s result, or a name for it. It selects the instrument the headers are checked against and supplies the fields the ticket does not; there is no path without one, so a batch that shares nothing still names one shared fact in its template. The ticket crosses as `FieldRows[TradeTemplate]`, the seam's row-or-rows form of [inputs.md](../../seam/inputs.md) decision 42, bound on the call against the template's instrument: the seam resolves the two handles, checks the width, the headers and each cell by its field's type, and hands the function typed columns; nothing here restates that. The result is a handle, text standing for the batch the seam keeps, `30512:trades:Henry Hub NYMEX:41`, the index's name between the kind and the count, or for a pair the two names joined by `+` in leg order, `30512:trades:A+B:41`, as [handles.md](../../seam/handles.md) says. A successful call publishes a batch and changes neither input; a recalculation with the same arguments shares the live batch, and a changed cell anywhere under it, a ticket value, the template, the index, makes a new one, the old released when Excel disconnects its last creator.

Under a `float_float` template, [float-float-spread.md](../../engineering-tickets/trade-valuation-pipeline/float-float-spread.md), the two indexes are a spread: the first index's price less the second's, paid against the row's `spread_price`, the ticket's price column under that name. With NTO's handle in I3 and PAN's in I4, and in I5 the collection of holiday calendars, which a `float_float` always names since it settles financially, `=_CreateTrades(I3:I4, A4:E4, A5:E5, B3, I5)` shows `30512:trades:NTO-PAN:41`, the names joined by `-` where a `fixed_float` pair's are joined by `+`. A positive quantity receives the first index and pays the second and the spread price; the indexes in the other order are the other spread. Since [float-float-units.md](../../engineering-tickets/trade-valuation-pipeline/float-float-units.md) the spread price is in the unit the batch types, two fields, `spread_price_currency_unit` and `spread_price_quantity_unit`, DOLLAR and BBL for dollars a barrel, required on every `float_float` and one each for the batch, the template's value or a ticket column every row agrees on; the two indexes may each quote in another, RB in dollars a gallon less WTI in dollars a barrel, [kernel.md](kernel.md).
